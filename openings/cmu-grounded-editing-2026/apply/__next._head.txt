5:T433,The project is about getting small language models to edit SVGs reliably from a natural-language instruction. An SVG is an unusual thing to ask a model to modify: the content is symbolic markup, but correctness is judged by what the file renders as, and the overwhelming majority of its characters are geometry that must survive the edit untouched. Three questions drive the work. How should a model's output be constrained so an edit can be verified before it is applied, rather than arriving plausible-looking and quietly wrong? How does a model connect a reference to an appearance — "the small one", "the shape in the corner" — to the element that actually produces it, when the markup itself describes no appearance at all? And when one instruction bundles several changes together, is it better to attempt it in a single pass or to decompose it into simpler edits that can each be checked?
